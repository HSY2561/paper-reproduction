# 实验训练计划

**问题**：面向四轮差速底盘与三自由度修复机构的道路裂缝分割、循迹和定点修复。

**方法主张**：以官方 BiSeNetV2 为固定视觉分割基线，针对裂缝像素占比低、细裂缝漏检、边界不连续和多尺度结构不完整等问题，逐步引入成熟的多尺度上下文、边界监督和类别不平衡损失模块，在保持机器人端实时性的条件下提升裂缝 IoU、Recall 和前景 F1。

**日期**：2026-09-22

## 先明确结论

可以按“先建立对比模型，再诊断 BiSeNetV2 的主要短板，再做单模块和组合消融，最后做公开测试集与机器人实验”的顺序推进。

“达到 SOTA”只能在**相同 Crack500 划分、相同测试口径和可复现训练协议**下讨论。不同论文的输入尺寸、数据划分、预训练权重、增强和最佳模型选择规则不同，不能把外部论文表格直接与本项目结果拼接后宣称 SOTA。实验目标应写成：

1. 在本项目统一协议下超过最强可复现对比模型；
2. 在裂缝 IoU、Recall、前景 F1 和部署效率之间取得更好的折中；
3. 证明提升来自模块本身，而不是参数量增加、测试集调参或训练预算增加。

BiSeNetV2 已由用户确定为工程基线。后续不再根据测试集排名重新选择基线；测试集只用于冻结模型后的最终报告。

| C2：模块能针对细裂缝和边界短板产生有效增益 | 单模块消融、组合消融、验证集错误类型分析 | B2、B3、B4 |

| 反主张：提升只是参数量增加或测试集调参 | 参数量/计算量对照、冻结测试集、验证集选模 | B3、B4 |

## 统一评价协议

### 数据和划分

- 数据集：Crack500。
- 训练/验证/测试：1896 / 348 / 1124 张。
- 测试集文件：`test.txt`；测试集在模型冻结前禁止用于调参和模块选择。
- 输入：BiSeNetV2 统一使用 400×400；若其他官方模型存在输入尺寸兼容问题，单独记录，不把兼容性修复写成模型性能优势。
- 随机种子：筛选阶段使用 42；最终基线和最终改进模型使用 42、43、44 三个种子。

### 训练和选模

- 训练预算：18,000 iterations，验证间隔 3,000 iterations。
- 保留每个验证点 checkpoint，不能只保留 mIoU 最优权重。
- 主选模指标：验证集裂缝 IoU；次级指标为裂缝 Recall 和前景 F1。
- mIoU 作为辅助指标，不能单独决定裂缝任务模型优劣。
- 先在验证集选择权重，再在测试集只评估一次。
- 各模型允许使用其官方推荐优化器、原生辅助头和原生损失，但必须完整记录配置。

### 指标

主指标：

- 裂缝 IoU；
- 裂缝 Recall；
- 前景 F1 = 2PR/(P+R)，其中 P、R 只取裂缝类别；

辅助指标：

- 裂缝 Precision；
- mIoU、Pixel Accuracy、Kappa；
- 参数量、FLOPs、峰值显存；
- 服务器 FPS/单张延迟；
- 目标板上的 FPS、延迟、功耗和显存占用。

注意：PaddleSeg 输出的多类平均 Dice 不能直接作为裂缝前景 F1，报告中必须同时列出裂缝类别 Precision、Recall 和由二者计算的前景 F1。

## 对比模型阶段

### B1：统一公开对比模型

**目标**：先建立一张可复现的 Crack500 对比表，明确 BiSeNetV2 的真实短板和最强对手。

必须运行：

1. BiSeNetV2：当前固定基线；
2. SegFormer-B0：轻量 Transformer 对比；
3. PIDNet-S：实时分割和边界分支对比，保留其 384×384 兼容记录；
4. HrSegNet-B32：与师兄论文路线直接相关的裂缝专用高分辨率基线；
5. PP-LiteSeg 或 STDC-Seg：面向边缘设备的实时分割对比；
6. U-Net 或 DeepLabV3+：经典通用分割对比，二选一作为主表模型。

建议附录补充：DeepCrack。只有在官方实现、数据接口和训练评价流程通过 smoke test 后才纳入正式比较，不能把未调通的实现作为负面结果。

模型来源要求：

- 优先使用官方 PaddleSeg 或论文作者公开实现；
- 不自行发明新的 backbone 或 decoder；
- 可以新建配置、训练入口和评估脚本，但模块实现必须来自公开成熟实现并注明来源；
- 记录代码版本、配置文件、预训练权重地址和 SHA256。

**B1 输出**：`public_baseline_results.csv`、统一比较表、参数/FLOPs/FPS 表、每个模型的训练日志和最佳验证权重。

**B1 通过条件**：至少有 5 个模型在同一 Crack500 测试集完成评估，且每个模型均有验证集选模依据。

## BiSeNetV2 问题诊断阶段

### B2：错误类型和短板分析

**目标**：决定模块优先级，而不是盲目堆模块。

在验证集上对 BiSeNetV2 进行：

- 细裂缝、粗裂缝、断裂裂缝、交叉/分支裂缝、低对比度裂缝、复杂纹理背景的可视化分组；
- 按裂缝面积占比、连通域数量、近似宽度和边界长度统计错误；
- 输出 FN、FP、断裂段、边界偏移和小目标漏检案例；
- 对比 SegFormer-B0 和 HrSegNet-B32 在相同图像上的错误模式。

**决策规则**：

- Recall 低、FN 多：优先类别不平衡损失和边界/细节监督；
- 裂缝 IoU 低但 Recall 尚可：优先多尺度上下文和边界约束；
- Precision 低、纹理误检多：优先上下文抑制和更严格的边界/损失设计；
- 参数量和延迟已经接近部署上限：禁止继续叠加重模块。

## BiSeNetV2 单模块消融阶段

### B3：三个核心成熟模块

固定 BiSeNetV2 主干、数据增强、输入尺寸、训练预算和随机种子，只改变一个因素。

| Run | 变体 | 目的 | 主要观察指标 |
|---|---|---|---|
| A0 | 原始 BiSeNetV2 | 对照基线 | 裂缝 IoU、Recall、F1、Params、FPS |
| A1 | BiSeNetV2 + OHEM CE 或 Dice-CE 类别平衡损失 | 减少裂缝类别漏检 | Recall、前景 F1 |
| A2 | BiSeNetV2 + ASPP/PPM 多尺度上下文模块 | 改善宽度变化、分支和断裂结构 | IoU、Recall、边界质量 |
| A3 | BiSeNetV2 + 边界辅助监督 | 改善细裂缝边界和轨迹连续性 | 裂缝 IoU、边界 F1、Recall |

模块选择原则：

- A1 优先使用 PaddleSeg 已有损失组件；
- A2 优先复用公开 ASPP/PPM 实现；
- A3 使用公开边界标签生成和边界损失/辅助头实现；
- CBAM/SE 只作为候选扩展模块，不进入第一轮核心消融，除非 A1-A3 都无法改善主要短板。

**单模块成功门槛**：相对 A0，至少满足以下一项且没有明显部署退化：

- 裂缝 IoU 提升 ≥ 2.0 个百分点；或
- 裂缝 Recall 提升 ≥ 2.0 个百分点；或
- 前景 F1 提升 ≥ 1.5 个百分点；
- 参数量增加不超过 20%，目标设备延迟下降不超过 15%。

没有达到门槛的模块不进入最终组合，除非错误分析显示它对机器人轨迹指标有明确价值。

## 组合消融阶段

### B4：组合和反参数量实验

在 B3 中保留下来的有效模块上运行：

- A0：原始 BiSeNetV2；
- A1、A2、A3：三个单模块；
- A12、A13、A23：两两组合；
- A123：三模块组合。

如果某个单模块没有通过门槛，删除包含它的组合，减少无效训练。

必须增加一个复杂度对照：

- 以接近 A123 参数量的加宽 BiSeNetV2，或
- 仅增加通道而不引入模块的参数匹配模型。

这样才能判断提升来自结构机制，而不是单纯增加参数。

**组合选择规则**：

- 先按验证集裂缝 IoU 排名；
- 若 IoU 差距小于 0.5 个百分点，按 Recall 和目标设备延迟排序；
- 若最终组合参数量增加超过 20%，必须有至少 2 个百分点的裂缝 IoU 或 Recall 增益，否则不进入最终模型。

## 最终确认阶段

### B5：最终公开比较和鲁棒性

冻结最终改进模型后，使用测试集完成：

1. BiSeNetV2 原版；
2. 最终改进模型；
3. B1 中最强的 2 至 3 个公开对比模型；
4. 参数匹配对照模型。

最终模型和原始 BiSeNetV2 使用 3 个随机种子，报告均值 ± 标准差；外部对比模型至少使用固定 seed 42，并在表格中明确标注。

**目标结果**：

- 在统一协议下，最终模型的裂缝 IoU、Recall 或前景 F1 至少有一项超过最强公开可复现模型 ≥ 1 个百分点；
- 不能以明显牺牲 Precision、FPS 或显存为代价；
- 若没有超过，论文应改写为“面向部署的有效改进”或“在精度-效率折中上有优势”，不宣称 SOTA。

### B6：机器人闭环验证

视觉模型冻结后再做系统实验：

1. 相机内参和像素-物理坐标标定；
2. 四轮差速底盘沿裂缝循迹；
3. 停车/粗定位误差；
4. 三自由度平台精定位误差；
5. 裂缝宽度测量 MAE、MSE、SD、CI；
6. 修复覆盖率 CR、未覆盖率 UR、溢出率 OR、均匀性 CUI；
7. 端到端处理时间和单次修复成功率。

- BiSeNetV2、SegFormer-B0、PIDNet-S、HrSegNet-B32、PP-LiteSeg/STDC、U-Net/DeepLabV3+；
- BiSeNetV2 的 A1-A3 单模块；

- 验证集选模和最终测试集评估；

### 可选运行

- DeepCrack；
- CBAM/SE；
- 三尺度或多尺度测试时增强；
- 多数据集迁移实验；
- 更大 SegFormer-B1/B2。

可选实验不能阻塞主线论文。如果核心模型尚未冻结，不先扩张到更多大模型。

## 风险与处理

- **测试集泄漏风险**：任何模块选择、阈值和训练策略只看验证集；测试集只在冻结后运行。
- **不同论文协议不一致**：外部论文数值只作背景参考；正式比较使用本项目重新训练的模型。
- **BiSeNetV2 原生多输出损失**：保留官方五输出监督，改进实验只改变明确指定模块。
- **PIDNet 输入尺寸问题**：继续保留 384×384 兼容配置，并在报告中单独说明。
- **模块堆叠过度**：每个模块先过单因素门槛，未改善主要指标的模块不进入组合。
- **只提高像素指标而损害机器人任务**：最终必须做循迹误差、精定位误差和 CR/UR/OR/CUI 验证。
- **无法达到公开论文数值**：先复核数据划分、预训练、输入尺寸、损失和选模规则；不能通过查看测试集反复调参来追赶数值。
